## 触发

lec-5/6/7 是手写扫描件，先让 agent 逐页转录成可读文字（PDF 有密码，
`pdftoppm` 渲染成图片绕过）。转录完一整块图算法之后，随口提了一句
「我想要自己探索整个问题，请你设计一系列的问题，驱动我逐个解决」。

它给了一份九模块的题梯（见 `lec/Graph/GRAPH.md`），按知识依赖排序、
不给答案。做下来发现这个模式比之前几周的用法好太多，才回头意识到之前那种用法有问题。

## 卡点 / 误解

**我原以为**用 agent 学习的正确姿势就是：读材料 → 有不懂的就问 → 它解释 →
我把想通的存进 cairn。这个循环看起来很合理，我跑了好几周。

**问题在于这个循环里我几乎没有挣扎过。** 问答模式下：

```
检索       agent 做
拆解       agent 做
推理       agent 做
评估答案   我做      ← 我全部的工作
```

我的角色只是**辨认**——读完点头说「哦，对」。辨认不是理解。三个月后
让我重新推一遍，我推不出来，因为那条路我根本没走过，只是看别人走过。

**这件事有个可观测的症状，我之前没看懂：** cairn 里好几条片段，卡点段
写起来很勉强，要么是「我不懂 X」（不是误解，是空白），要么干脆是在
复述 agent 给的正确答案——那正是质控闸门里明确要丢掉的两类。
**不是我不会写片段，是问答模式压根不产生认知轨迹。** 没有摔过的坑，
自然没有坑可记。

## 关键 insight

**agent 真正的比较优势不是「知道答案」——那是书的强项，而且书写得更好。
是「知道依赖顺序」和「知道难点在哪」。**

一份九模块的题梯编码的正是这个：什么必须在什么之前想通、哪一步历史上就是难的
（模块 6 的 Kosaraju 它明说了「提示会重一点」）、哪些坑值得让你先踩一次
（Q7.1「DFS 行不行？找个小图跑一遍看哪里出问题」——它故意让你去撞那堵墙）。

这个能力书给不了：书是线性铺开的，不会为你当前的位置重排顺序，
也不会在你正要踩坑的地方把坑摆到你面前。

角色一换，推理那一步就换到我这边了：

```
            问答模式          题梯模式
检索        agent             agent（转录、铺底）
拆解        agent             agent ← 它的真本事
推理        agent             我   ← 换过来了
评估        我                agent（对答案时才介入）
```

### 这一轮跑通的流程

**1. 铺底** —— 让 agent 把材料变成可读的。这次是逐页转录手写扫描件
（PDF 有密码，`pdftoppm` 渲染成图片绕过）。**这一步不能省**：
零基础直接上题梯会卡死在第一个模块。

**2. 出题梯** —— 一句话就够：「我想要自己探索整个问题，请你设计一系列的问题，
驱动我逐个解决」。按知识依赖分模块、模块内递进、不给结论。
只在历史上确实难独立想出的地方把提示加重（它自己标了模块 6 Kosaraju
「提示会重一点」）。

**3. 我推** —— 这一步替我做等于毁掉它。说「我卡住了」不等于「替我做」。

**4. 对答案** —— 两条规矩：agent 先自己独立推一遍再看我的（顺着我的思路找补，
会把错的地方一起合理化掉）；**指出缺口，不要重写**——说「这一步缺了 XXX 的
论证」，而不是给一份完整的正确证明。

**5. 归档** —— 每个模块做完、或一个卡点刚解开就存。题梯本身也要存成文件，它只活在对话里的话，压缩一到就没了。

**顺带解决了 cairn 的原料问题。** 题梯模式下每个模块都在制造真实的卡点，
片段的「我原以为」终于有东西可写。见 [[halve-is-not-log]]——那条是少数几条
真从卡点里长出来的，和那些勉强的一对比就看得出差别。

去掉课程细节之后的蒸馏版在 Anamnesis 仓库的 `docs/questionToKnowledge.md`——
那篇是可迁移的部分，这条是现场。

## 遗留问题

- [ ] 题梯的粒度怎么定？这次是「一整块图算法」拆九个模块。如果只学一讲，
      拆三四个模块会不会太碎、反而打断思路？还是说粒度应该跟着依赖链的长度走，
      而不是跟着课时？
- [ ] 对答案的环节还没找到好形式。现在是「我做完来问」，但这样 agent 看到的是
      我的成品，看不到我卡在哪、试错了什么——而卡点恰恰在试错过程里。
      要不要让我把草稿也交出去？
