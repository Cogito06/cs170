## 触发

看 lec-4 里 QuickSelect 期望运行时间 O(n) 的证明，自己先看了一遍，跟 agent 一起
把逻辑链捋了一遍。具体卡住的地方不是算不出来，是**想不出「分阶段」这个念头本身**
是从哪冒出来的。

## 卡点 / 误解

**卡在「怎么想到分阶段」，不是「分阶段之后怎么算」——后者纯代数，前者才是这个
证明唯一需要巧思的地方。**

标准递归树分析（[[log-n-is-the-depth]] 那套）默认**每一层的规模是确定的**——
这是套用主定理的前提。这个假设被随机性打破了：好 pivot 把规模缩到 3/4，差 pivot
几乎不缩，同一轮的规模不再是深度的固定函数。这时候直觉还是会继续按"第几轮"分组
去凑代价，但轮数本身就是随机的、代价也跟着随机，两个随机量绞在一起没法直接求和——
这是卡住的地方，也是为什么直接照搬递归树那套行不通。

**真正的诀窍是换记账单位**：不按"第几轮"分组，按"规模掉到哪个门槛（n·(3/4)^i）"
分组。这一刀切下去，两件事被解耦了：

```
阶段 i 要转几轮   —— 随机（好 pivot 出现前要等几次，几何分布）
阶段 i 每轮花多少 —— 确定（规模单调不增，上限从进入阶段那刻起就锁死，
                       差 pivot 再磨也翻不出这个上限）
```

随机性被关进「轮数」这一个变量里，「每轮代价」彻底脱离随机性，之后才能套期望的
线性性把两边拆开算：

```
E[T(n)] = E[ Σᵢ L(i)·O(n(3/4)^i) ]
        = Σᵢ E[L(i)]·O(n(3/4)^i)     ← 线性性：L(i) 随机、O(n(3/4)^i) 确定，才能拆
        = Σᵢ 2·O(n(3/4)^i)            ← E[几何分布] = 1/p = 2
        = O(n)·Σᵢ(3/4)^i = O(n)
```

## 关键 insight

**这个「解耦」模式不是 SELECT 专属的**——凡是"递归规模的衰减速率本身是随机的"
的分治算法，大概率会用同一个骨架：按已达成的规模门槛重新分组，把"要等几次"
（随机，通常是几何分布）和"每次值多少钱"（一旦分组就确定）拆成两个独立的求和
维度，再靠线性性合并。以后遇到别的随机分治算法（比如随机快排的平均情形分析），
先问一句「规模的衰减率是不是随机的」——如果是，这个模式大概率能直接套。

这一节的 `a=1` 也是 [[per-node-not-per-level]] 框架第一次给出的**根重**具体例子——
之前存的 Karatsuba / Strassen（见 [[karatsuba-cant-reach-balance]]）都是叶重。
`a=1, b=4/3, d=1`：判别式 `log_b 1 = 0` 对任何 `b>1` 恒成立，跟"好 pivot"的门槛
具体取 3/4 还是 9/10 完全无关——幻灯片特意换了个门槛验证同一个结论，就是在演示
这一点。
