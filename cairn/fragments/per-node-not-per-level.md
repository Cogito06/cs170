## 触发

学主定理 `T(n) = a·T(n/b) + f(n)`，自己动手推的时候卡在记账上——
得先把**求和项和递归项**分清楚，否则中间那步化简就是糊的。

## 卡点 / 误解

**最容易翻车的地方：把 `f(n) = n^d` 当成「这一层」的代价。**

它不是。它是**一个节点**的代价，而且是这个节点**除去递归调用之外**真正干的活
（归并、拆分、加法……）。要得到层代价，必须先数这层有几个节点。

把两个项的职责钉死：

```
T(n) = a·T(n/b) + f(n)
       └───┬───┘   └┬─┘
        递归项      求和项
        只负责生孩子   这个节点自己干的活
        (a 个，规模 n/b)   (不含递归调用)
```

判决性的一步是第 k 层的化简——**两个项各出一半，相除才出东西**：

```
第 k 层：  节点数 a^k  ×  每节点 (n/b^k)^d

         = a^k · n^d / b^(kd)

         = n^d · ( a / b^d )^k
                  └───┬────┘
              递归项给的 a^k（增殖）
              求和项给的 b^(−kd)（衰减）
              两者一除 = 每层的净倍率
```

这一步要是没把 `a^k` 和 `n^d` 分开写，后面就再也化不出那个比值。

## 关键 insight

**整个主定理被压缩成一个几何级数**，剩下全是它的三种行为：

```
              L
T(n) = n^d ·  Σ  r^k ,   r = a/b^d ,  L = log_b n
             k=0
```

我原来的直觉「`d = log_b a` 的分类其实是一种权衡」是对的，而且**天平就是 r**：

```
r = a/b^d ⋛ 1  ⟺  a ⋛ b^d  ⟺  log_b a ⋛ d
     ↑分支增殖率  ↑规模衰减率
```

所以「比较 d 和 log_b a」只是「比较 r 和 1」的换写，是同一件事的两种记法。

三种结果各有一句人话：

```
r < 1  根赢   Θ(n^d)            答案 = 顶层代价
r = 1  平局   Θ(n^d log n)      答案 = 单层代价 × 层数
r > 1  叶赢   Θ(n^(log_b a))    答案 = 叶子数
```

平局那行的 log 是什么，见 [[log-n-is-the-depth]]。

最后一行值得单说：`n^(log_b a)` 不是什么神秘指数，**它就是叶子数**——
因为 `a^(log_b n) = n^(log_b a)`，左边就是「a 叉树长 log_b n 层有几片叶子」。
叶重情形的答案说白了就是「数叶子」。

天平三个参数里通常只有一个能调，见 [[karatsuba-cant-reach-balance]]。
