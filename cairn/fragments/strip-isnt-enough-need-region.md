## 触发

问 Closest Pair 分治算法里，为什么合并步骤对带里每个点的比较是 O(1) 次。
紧跟着刚讨论完的 QuickSelect 阶段论证（[[phase-by-size-not-round]]），是同一节课
紧接着的下一个例子，但证明手法完全不一样。

## 卡点 / 误解

**我原以为**：只要把跨中线的候选对限制在宽度 `2d` 的带状区域（strip）里，问题
就已经解决——带外的点距离必然 > d，肯定不用比较，所以带内暴力两两比较就该行了。

**实际不是。** 带的限制只回答了「哪些点可能有用」，没有限制「带里有多少点」——
最坏情况下 n 个点全挤在中线附近，带内仍是 O(n) 个点，两两比较还是 O(n²)，
没有真正解决问题。

**真正管用的收紧**：对带里每一个点 p，进一步把要比较的对象限制到一个更小的矩形
region R（宽 d、高约 d，只往 y 方向前进 d 距离内看，靠带内已经按 y 排好序才能
只往前看）。然后**证明 R 里最多 8 个点**——用鸽巢原理：

```
把 R 切成 8 个 d/2 × d/2 的小格子
假设 R 里点数 > 8  →  鸽巢原理：至少一个格子塞进 ≥2 个点
同一格子里两点距离 ≤ 对角线 = (d/2)·√2 ≈ 0.707d < d
格子边长只有 d/2 < d  →  格子不可能跨中线  →  这两点在同一侧
但 d = min(δL, δR) 本来就是"同侧任意两点距离"的下界  →  矛盾
```

这个证明里有一步容易漏掉的巧思：**d 被反复利用**——它先是递归子问题给出的
候选答案，然后被当成一把尺子，反过来去限定合并步骤的搜索范围。不是「先算完
答案再去优化枚举」这种先后关系，是**递归的输出本身被塞进了证明合并步骤复杂度
的论证链条里**。

## 关键 insight

和刚存的 [[phase-by-size-not-round]] 正好构成一组对照，两者都是「划一个门槛
区域 + 证明区域内数量是常数」的套路，但工具完全不同：

```
QuickSelect 的 O(n) 期望   ——  概率论断：平均情况下代价小（几何分布）
Closest Pair 的 O(1) 上界 ——  组合论断：最坏情况下代价也小（鸽巢原理，无随机性）
```

同一节课前后脚出现，容易在脑子里混成一类——一个答的是"期望多快"，一个答的是
"最坏情况下这个数能不能超过某个常数"，是概率论和纯几何组合两套完全不同的工具。

另外这也是 [[per-node-not-per-level]] 框架下第三个"刚好落在天平中点"的具体例子：
`a=2, b=2, d=1`，跟归并排序参数完全一样，续上 [[karatsuba-cant-reach-balance]]
讲的"边界算法是设计出来的"这条线。
